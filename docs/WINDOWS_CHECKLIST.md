# Windows PC에서 확인할 것 (2026-10-19 작업분)

자동 테스트와 CI의 Windows 빌드는 모두 통과했지만, 실제 화면 조작과 Finale·MuseScore에서 여는 것은 사람이 확인해야 한다. 결과를 알려 주면 그에 맞춰 고친다.

## 준비
1. https://github.com/immanueladmin1985-dev/scorestudio/releases/download/latest/ScoreStudio-win-x64.zip 을 내려받아 압축을 풀고 `ScoreStudio.exe`를 실행한다(.NET 8 Desktop Runtime 필요).
2. 압축을 푼 폴더의 `samples\musicxml\finale-marks.musicxml`은 이번에 추가한 기호가 모두 들어 있는 시험용 악보다.
3. Finale에서 내보낸 실제 MusicXML 파일(예: "다윗의 노래")을 하나 준비한다.

## 1. MusicXML 내보내기
- [ ] 파일 > 가져오기 > MusicXML로 Finale에서 내보낸 파일을 연 뒤, 파일 > 내보내기 > MusicXML로 `.musicxml`과 `.mxl` 두 가지를 저장한다.
- [ ] 저장한 파일을 Finale에서 연다: 음표, 가사, 코드 이름, 도돌이표·볼타, 셈여림, 이음줄, 아티큘레이션이 원본과 같은가?
- [ ] (있으면) MuseScore에서도 열린다.
- [ ] 가져온 원본 파일과 같은 이름으로 내보내려 하면 거절하는가?

## 2. 기호 가져오기와 화면 표시
- [ ] Finale 파일을 가져올 때 결과 창의 경고 목록에서 셈여림, 이음줄, 아티큘레이션, 크레셴도, 글자 지시, 페르마타, 메트로놈이 사라졌는가? (남은 경고가 무엇인지 알려 주면 다음 작업에 반영한다.)
- [ ] 화면에서 기호 위치가 Finale 악보와 비교해 어색한 곳이 있는가? 특히 다음을 본다.
  - 스타카토·악센트가 음표머리 쪽에 붙는가
  - 이음줄이 음표를 가리지 않고 넘어가는가, 다음 줄로 넘어가는 이음줄이 이어지는가
  - 셈여림·크레셴도가 가사와 겹치지 않는가(가사가 있는 보표에서는 보표 위로 간다)
  - 피아노 악보에서 다른 보표로 가는 이음줄(알려진 문제: 모양이 어색함)

## 3. 기호 넣기 도구 (왼쪽 도구 팔레트의 "아티큘", "표현", "이음줄")
- [ ] **아티큘**: 음표를 누르면 메뉴가 뜨고, 고른 기호가 붙는가? 같은 것을 다시 고르면 빠지는가? 음표를 고른 뒤 S·A·T·V·W·F 키, Delete가 되는가?
- [ ] **표현**: 음표나 빈 자리를 누르면 셈여림 메뉴가 뜨는가? 숫자 키 1~8(pp, p, mp, mf, f, ff, sfz, fp)이 되는가? T(글자 창), M(메트로놈 창)이 되는가?
- [ ] **이음줄(스마트 도형)**: 시작 음표 → 끝 음표를 누르면 이음줄이 생기는가? Shift+, (<)·Shift+. (>)로 크레셴도·디크레셴도를 고를 수 있는가? 시작 음표를 고르고 Delete로 지워지는가? Esc로 취소되는가?
- [ ] 모든 기호 넣기를 Ctrl+Z로 되돌릴 수 있는가?
- [ ] 넣은 기호가 저장 후 다시 열어도 남는가? MusicXML로 내보내 Finale에서 열어도 남는가?

## 4. Finale와 다르게 느껴지는 점 (가장 중요)
단축키 기본값 일부는 Finale 매뉴얼을 직접 확인하지 못해 추정으로 정했다. 아래가 Finale와 다르면 알려 준다(편집 > 단축키 설정에서 바로 바꿀 수도 있다).
- [ ] 아티큘레이션 메타도구 키: S 스타카토, A 악센트, T 테누토, V 마르카토, W 스타카티시모, F 페르마타
- [ ] 표현 메타도구 숫자 키의 셈여림 순서: 1 pp, 2 p, 3 mp, 4 mf, 5 f, 6 ff, 7 sfz, 8 fp
- [ ] 스마트 도형 키: S 이음줄, < 크레셴도, > 디크레셴도
- [ ] Speedy Entry에서 ↑↓가 음표를 옮기는지(이전부터 남은 확인 항목)
- [ ] 그 밖에 Finale에서 쓰던 방식과 달라 불편한 점

## 5. Finale 파일(.musx) 열기
- [ ] 파일 > 가져오기 > Finale 파일(.musx)로 먼저 압축을 푼 폴더의 `samples\musx\zwei_gesange.musx`(Brahms)를 열어 본다. 그다음 **가지고 있는 실제 .musx 파일**(성가곡, 피아노곡, 합창곡)을 연다. 오류 없이 열리는가?
- [ ] Finale에서 보던 악보와 비교해 빠지거나 틀린 것: 음표·가사·코드 이름·셈여림·이음줄·반복 기호·줄 나눔
- [ ] 이조 악기(클라리넷 등)가 있는 악보는 MusicXML로 내보내 Finale에서 열었을 때 소리 높이가 맞는가?
- [ ] 결과 창의 경고 목록(꾸밈음, 트릴 등 남은 것)을 알려 준다. 다음 작업 순서를 정하는 데 쓴다.
- [ ] 꾸밈음: `samples\musx\grace_notes.musx`, `samples\musicxml\grace-notes.musicxml`, `v1v2tuplets.musx`를 열어 꾸밈음이 작은 음표로 주음 앞에 보이는가? 빗금·빔이 Finale와 비슷한가?
- [ ] 장식음·트레몰로: `samples\musicxml\ornaments.musicxml`을 열어 트릴·턴·모르덴트, 트레몰로 빗금과 두 음 트레몰로 줄, 울림 붙임줄이 Finale와 비슷한가?
- [ ] 남은 기호: `samples\musicxml\finale-marks-2.musicxml`을 열어 아르페지오(물결선·화살표·괄호), 하모닉·올림활·내림활, 리허설 마크(네모 A, 네모 없는 Coda), 글리산도(물결선)·슬라이드(곧은 선), 갈고리가 달린 괄호선, cresc. 뒤의 점선, 트릴 뒤의 물결선이 Finale와 비슷한가? 가지고 있는 .musx 파일에 이런 기호가 있으면 그 파일로도 확인한다.
- [ ] 아티큘레이션 도구 메뉴에 하모닉·올림활·내림활 등이 이름대로 나오고 붙는가?
- 원본 .musx 파일은 바뀌지 않는다. 문제가 있는 파일은 저작권이 있을 수 있으므로 저장소에 올리지 않고 결과만 기록한다.
