# 꾸밈음

Finale 호환 작업에서 `.musx` 시험 파일 220개를 가져올 때 가장 많이 남은 경고였다(17개 파일, `docs/MUSX_IMPORT.md`). 사용자가 Windows에서 연 `v1v2tuplets.musx`에서도 경고로 나왔다.

## 데이터 모델 (스키마 18 → 19)
꾸밈음은 마디 안에서 시간을 차지하지 않으므로, 따로 된 음표(`ScoreEvent`)로 두지 않고 꾸밈음이 붙는 음표에 목록으로 둔다. 그래서 길이·위치·잇단음표·마디 길이 계산은 바뀌지 않는다.

| 대상 | 추가 항목 | 설명 |
|---|---|---|
| `ScoreEvent` | `GraceNotes: List<ScoreGraceNote>` | 이 음표(또는 쉼표) 앞에 연주하는 꾸밈음, 순서대로. 화음에서는 첫 음표가 갖는다. |
| `ScoreGraceNote` | `MidiPitch`, `NotationSpelling` | 음높이와 철자(일반 음표와 같은 규칙) |
| | `Type` | 기보 길이: `eighth`(보통), `16th`, `32nd`, `64th`, `quarter`, `half` |
| | `Slash` | 기둥에 빗금(아차카투라) |
| | `Chord` | 앞 꾸밈음과 같은 기둥(꾸밈음 화음) |
| | `After` | 음표 뒤에 온다(Finale에서 마디 끝에 둔 꾸밈음) |

- 버전 18 이전 파일은 빈 목록으로 열린다. 없는 음높이나 모르는 길이는 손상 파일로 거절한다.

## MusicXML
- 가져오기: `<grace>`가 있는 음표를 모아 같은 보표·성부의 다음 음표(또는 쉼표)에 붙인다. 마디 끝까지 붙을 음표가 없으면 그 성부의 마지막 음표 뒤 꾸밈음(`After`)이 된다. `slash="yes"`는 빗금, `<chord/>`는 꾸밈음 화음이다.
- 꾸밈음에서 시작하는 이음줄(꾸밈음과 주음을 잇는 관례적 이음줄)은 저장하지 않고 경고도 하지 않는다.
- 쉼표 꾸밈음과 타악기 꾸밈음은 경고하고 가져오지 않는다.
- 내보내기: 주음 바로 앞(뒤 꾸밈음은 바로 뒤)에 `<grace>` 음표로 쓴다. 기둥은 위, 짧은 꾸밈음 화음이 둘 이상이면 빔으로 묶는다.

## 그리기
- 보통 음표의 0.6배 크기, 기둥은 위. 주음의 임시표 왼쪽에 둔다(뒤 꾸밈음은 주음 오른쪽).
- 꾸밈음 화음 하나: 꼬리, 아차카투라는 기둥에 빗금. 8분음표보다 짧은 꾸밈음 화음이 둘 이상: 수평 빔(가장 짧은 값만큼의 빔 수).
- 조표와 다른 음에는 작은 임시표, 오선 밖이면 작은 덧줄.
- 마디 간격 계산에 꾸밈음 자리를 넣는다.

## 아직 없음
- 꾸밈음 입력(Finale Speedy Entry의 `;`). 키 설정 창에 "아직 지원하지 않음"으로 남겨 둔다.
- 꾸밈음의 점, 꾸밈음과 주음을 잇는 이음줄 그리기, 꾸밈음 가사.

## 수용 기준과 결과 (2026-10-19)

2. 모든 샘플의 내보내기 왕복이 같다. 내보낸 파일이 MusicXML 4.0 스키마를 통과한다(16개). — 통과
3. 그리기: 꾸밈음이 작게, 주음 앞에, 꼬리·빗금 또는 빔과 함께 그려진다(`MarksLayoutTests`). — 통과
4. 저장·재열기, 버전 18 파일 열기, 잘못된 값 거절. — 통과
5. `.musx` 시험 파일 220개: 모두 열리고, 꾸밈음 경고가 사라져 경고 없는 파일이 139 → 149개. — 통과
